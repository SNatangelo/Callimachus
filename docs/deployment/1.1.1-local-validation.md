## Transfer the complete change

The PR includes production code, regression tests, fixtures, version metadata and
the existing native packaging scripts. Apply the complete PR to the matching
base in the target Callimachus repository; do not copy only the last commit.
Review conflicts against the target repository before merging. No local `.t`,
`knowledge`, credentials, run databases or downloaded corpus is a runtime
dependency. Local audit evidence is summarized separately in
[the validation checkpoint](../architecture/reference-identity-validation-checkpoint.md).

For an offline transfer, export the PR commits with `git format-patch` against
the PR base, or create a Git bundle containing the branch and its base. Keep the
base and head commit IDs with the export. A source archive is sufficient to
inspect code; the existing build requires genuine Git revision metadata.

## Build the same revision on each operating system

Use a fresh checkout of the chosen PR commit for each platform, Python 3.13.15,
and a separate virtual environment. Keep temporary files, caches, logs and
outputs in the checkout or an explicitly authorized build workspace. Do not
overwrite an earlier package. The packaging constraints already define the
dependencies; no additional production dependency is introduced here.

From that checkout, using its native Python environment:

```text
python -m pip install --only-binary=:all: -r requirements.txt -r requirements-gui.txt -r requirements-ocr.txt -r requirements-rag.txt -c packaging/release-constraints.txt
python -m pip install --only-binary=:all: pyinstaller==6.22.3 pytest -c packaging/release-constraints.txt
python -m pip check
python -m pytest tests/test_desktop_build.py tests/test_desktop_licenses.py tests/test_desktop_matrix.py tests/test_windows_installer_build.py tests/test_packaged_runtime.py tests/test_invocation.py tests/test_cli_help.py tests/test_desktop_command.py -q
python packaging/build_desktop.py
python packaging/smoke_desktop.py
```

On Windows, also run `packaging/build_windows_installer.py` and
`packaging/smoke_windows_installer.py` if producing the installer, then
`python packaging/archive_desktop.py windows-x64`. The installer requires NSIS;
follow the prerequisites documented by its existing build script.

On Linux/WSL, use `QT_QPA_PLATFORM=offscreen` for tests and smoke checks. The
existing workflow lists the required Qt system libraries. Use the established
Ubuntu 22.04 build environment when targeting its library baseline; a package
built directly on a newer WSL distribution has that distribution's baseline.
Run `python packaging/collect_ubuntu_sources.py` for redistributed Ubuntu
libraries, then `python packaging/archive_desktop.py linux-x64`.

For macOS, run the same commands **inside the macOS guest**, with Apple Command
Line Tools installed, then `python packaging/archive_desktop.py macos-x64` for
the existing Intel VM. WSL hosts the VM; Linux itself is not the macOS compiler
environment. An Intel VM does not validate ARM64. The existing build uses ad hoc
signing; Developer ID signing and notarization are separate publication steps.

Keep the package SHA-256 sidecar, `build/desktop/build-metadata.json`, dependency
versions, test/build/smoke logs and process exit codes. Confirm that all packages
report the same version and source revision before handing them to the operator.

## Acceptance remains evidence based

The fixed evaluation scope is the original 1,988 references (1,928 annotated
positives) and the historical 18 documents (1,427 references, 120 annotated
positives). Unannotated references do not establish accuracy. Older scores must
not be relabeled as results of this build. Source tests, literal-reference
retention, live acquisition counts and independently annotated identity accuracy
are separate checks. Successful packaging does not establish bibliographic
accuracy or prove that a Windows Sandbox crash is resolved.

After the operator tests the local packages and approves publication, transfer
the reviewed change to Callimachus and run its GitHub native build workflow.
